# Repository review decisions and naming conventions

Semantic Model Cleaner reads `.smc-policy.json` from the project directory during `smc check`. Commit this local JSON file to share review decisions and naming conventions with the team. No paid service or remote storage is required. A missing default file means no configured policy; malformed policies and explicitly selected missing files fail with exit 2.

```sh
smc policy init ./project
smc policy show ./project
smc policy validate ./project
smc check ./project --fail-on warning
```

A minimal naming policy:

```json
{
  "schema_version": "1.0",
  "decisions": [],
  "naming_rules": [
    {"id": "measure-display", "item_type": "Measure", "case": "title"},
    {"id": "dimension-prefix", "item_type": "Table", "table_pattern": "Dim*", "prefix": "Dim_"}
  ]
}
```

The stored `digest` is generated by the app when saving. It supports optimistic concurrency; it is not a signature or a trust certificate. To edit through the API, submit the digest returned by the preceding read as `expected_digest`. Concurrent edits are rejected rather than overwritten. Saves replace the policy atomically and use an exclusive short-lived lock. After a process interruption, inspect a remaining `<policy>.lock` and confirm no policy update is running before removing it.

## Saved decisions

Run `smc check` to obtain canonical finding fingerprints, then record an accountable decision:

```sh
smc policy add ./project --finding <fingerprint> --disposition keep \
  --reason "Required for the planned release" --owner "Model team" --expires-on 2026-12-31
smc policy remove ./project --id <decision-id>
```

`--model` selects a model path relative to the project. Repeatable `--report` options in `policy add` and `naming preview` select exact report paths relative to the project. These differ from the existing `check --report` name filters. All selected reports must be bound to the model. Without explicit reports, connected local reports are discovered.

Each decision stores exactly: `id`, `rule_id`, `finding_fingerprint`, `evidence_fingerprint`, `scope_fingerprint`, `disposition`, `reason`, `owner`, and `expires_on`.

- Reason and owner must be nonempty. Expiry uses `YYYY-MM-DD`, inclusive through that UTC date. Expired decisions remain visible but do not suppress a warning.
- Dispositions `keep`, `accept`, and `defer` acknowledge an eligible warning until expiry. `note` only annotates it.
- Only **SMC004 (unused item), SMC005 (stale metadata), and SMC009 (naming suggestion)** warning findings can be suppressed by a decision. Broken references, coverage limitations, naming conflicts, and other errors remain actionable. Decisions attached to protected findings are shown as `noted` and do not suppress them.
- Decisions never enter the deletion authorization path. A saved `keep` or `accept` is review context, not permission to delete. Existing cleanup blockers remain enforced.
- Findings remain in CI output, including the saved reason, owner, expiry, and review state. A decision is not a repair and does not remove the underlying reference or issue.

The finding fingerprint identifies a rule/location/item. Evidence additionally hashes the entire source file; editing another item in the same TMDL file can conservatively invalidate the decision. Scope fingerprints include the relative model path and exact selected report paths. Moving the complete checkout preserves fingerprints; changing report selection or source content makes the decision stale. Returning to the same evidence and scope can reactivate an unexpired decision. Decisions are not automatically transferred across renames.

`smc check` adds `evidence_fingerprint`, `scope_fingerprint`, `review_status`, and `review_decision` to findings, plus policy metadata and accepted/stale/expired counts. Review status is `unreviewed`, `stale`, `expired`, `accepted`, or `noted`. The established baseline mechanism remains separate and backward compatible. A baseline is not converted into an accountable decision automatically.

## Naming suggestions and reviewed changes

```sh
smc naming preview ./project
smc naming preview ./project -o ./naming.plan.json
smc diff ./naming.plan.json
smc apply ./naming.plan.json
```

Naming never invokes writers against the original project during suggestion generation. `naming preview` uses the existing change-plan engine, which stages copies, rewrites selected report references, validates static integrity, and exports exact diffs. Applying remains a separate existing `smc apply` operation. Policy and plan output files cannot overwrite selected artifact metadata.

Rules require unique `id` and `item_type` (`Table`, `Measure`, or `Column`; Column includes calculated columns). Optional fields:

| Field | Default | Behavior |
|---|---|---|
| `table_pattern` | `*` | Case-insensitive shell-style pattern against the original table name. |
| `find` / `replace` | empty | Literal substring replacement, with no regex or executable code. |
| `prefix` / `suffix` | empty | Add the configured affix; an existing exact affix is preserved once. |
| `case` | `preserve` | `preserve`, `snake`, `pascal`, or `title`; splits lower-to-upper camel transitions and whitespace/underscore/hyphen boundaries. |

Rules run in array order. Case transforms can change acronym capitalization; inspect the proposed names. Conflicting final names, empty/invalid names, and transforms that continue changing names on a second pass block plan creation. Use a prefix rule instead of a replacement that repeatedly inserts itself. Cyclic swaps or other writer restrictions can also be rejected by the existing plan engine.

CI emits SMC009 warnings for naming suggestions and SMC010 errors for conflicts. SMC010 cannot be suppressed by policy decisions or baselines. A naming suggestion is not applied merely because CI reports it.

## Python/UI integration contract

All functions are in `semantic_model_cleaner.review_policy` and raise `PolicyError` (a `ValueError`) for invalid policy operations. Naming can also raise the existing change-plan `PlanError`.

```python
load_policy(workspace, path=None) -> policy_with_digest
validate_policy(policy) -> normalized_policy_with_digest
save_policy(workspace, policy, path=None, expected_digest=None) -> policy_with_digest
review_findings(workspace, model_path, report_paths) -> check_envelope
add_decision(workspace, finding, scope, *, disposition, reason, owner, expires_on, path=None) -> policy_with_digest
remove_decision(workspace, decision_id, path=None) -> policy_with_digest
naming_proposals(model_path, policy) -> {ok, proposals, conflicts, operations}
naming_preview(workspace, model_path, report_paths, policy=None) -> {ok, proposals, conflicts, operations, plan}
```

`review_findings` uses explicit report paths and the same canonical CI pipeline. Submit one returned finding and its returned `scope` to `add_decision`; it recomputes the current evidence and rejects stale or fabricated findings. The naming preview's `plan` is null when there are no changes or when naming conflicts exist. `save_policy` requires `expected_digest` when a policy already exists. Paths must stay inside the project and outside Semantic Model/Report artifacts.

CLI exits: 0 success, 1 naming conflicts, 2 invalid input/validation failure. `smc check` retains its existing threshold-dependent 0/1/2 contract.
