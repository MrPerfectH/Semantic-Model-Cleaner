# Semantic Model Cleaner 0.4.0

0.4.0 is the first stable release. It contains every change since 0.4.0b10.
The VS Code extension **0.2.0** bundles this engine and is the first stable
Marketplace release of `MrPerfectH.semantic-model-cleaner`.

## Install

- **VS Code (recommended):** install **Semantic Model Cleaner** from the
  Extensions view. Marketplace selects the native package for Windows x64,
  Linux x64, macOS Intel or macOS Apple Silicon. No Python setup is required.
- **Windows app:** download `semantic-model-cleaner-windows-x64-0.4.0.zip` and
  its `.sha256` file from this release, verify the checksum, extract the whole
  ZIP and run `Semantic Model Cleaner.exe`.
- **CLI / Python:** `python -m pip install semantic_model_cleaner-0.4.0-py3-none-any.whl`
  (Python 3.11 or newer).

## Changes since 0.4.0b10

### Self-contained VS Code extension

- Native packages bundle the engine, Python runtime, templates, schemas and
  notices. Open Cleaner uses the bundled engine; explicit Python Path or
  Executable overrides still work.
- Each package is installed and tested in CI with external networking blocked,
  including exports, plan apply, verify and byte-exact restore.

### Reports screen

- The Reports screen leads with what is missing from the model: one row per
  missing table, column or measure, sorted by visible impact, with the Reports
  and pages that use it.
- Fixes stay human-reviewed. Pick a replacement and review the plan; nothing is
  written directly. A broken measure reference can now point at a measure in
  another table.

### Safer cleanup scope

- Model changes (delete, rename, move, promotion, auto-date removal) are refused
  when connected Reports are not selected or their binding cannot be verified.
  Apply rechecks the reviewed Report scope before writing.
- Without every connected Report, unused items stay at **Review** instead of
  **Safe**.
- Cleanup dependencies are limited to the chosen model and its connected Reports.
- Report Extension Measure deletion is guarded by the same dependency checks as
  model measures.
- Declaration-owned descriptions are preserved when TMDL objects are removed.

### New cleanup and CLI features

- All-or-nothing cleanup of unused auto-date tables.
- One-step cascade cleanup plan: `smc plan PROJECT --model-path MODEL --cleanup unused --cascade -o cleanup-plan.json`,
  with every blocker explained in JSON output.
- PROJECT-relative `--model-path` and repeatable `--report-path` on every project
  command. Operation `report_paths` also resolve relative to PROJECT.
- Configurable blocking and advisory CI rules, unused-item filters and
  coverage requirements for `smc check`; `smc review` accepts `--policy` and
  `--baseline`. Markdown summaries with `--summary-output`.
- A generated agent skill ([SKILL.md](../../SKILL.md)) for AI agents.

### Performance

- Faster analysis and plans on large projects. On an 8-Report project, `smc usage`
  dropped from 35 s to 8 s and a column rename plan from 90 s to 41 s. Bulk plans
  reuse analysis across processes.

## Known limits

- The Windows executable is not Authenticode-signed; Windows may show a
  reputation warning.
- macOS engines carry an ad-hoc signature and are not notarized.
- Saved changes are withheld for model scopes that contain UTF-8 BOM-prefixed
  TMDL files.
- Analysis covers local TMDL and PBIR files only. Reports published outside the
  local project are not discovered.
