# Semantic Model Cleaner 0.4.0b3 public beta

This beta corrects stale-reference classification, explains model analysis limits,
and makes item details and table navigation easier to read.

## Changes

- Working slicers and unfiltered “All” filter cards retain their live field usage.
  Stale cleanup previews use the same supported candidates as the CLI and writer.
  Inactive missing-field cards and orphan bookmark states require explicit review
  instead of being removed by bulk stale cleanup.
- Model analysis limitations appear separately from report health. Each limitation
  identifies the model feature and source; counts distinguish feature occurrences
  from affected items. Perspective membership is explained as a model reference,
  not a broken report.
- Calculation-group selector and ordinal columns show their structural role.
  Known calculation-expression dependencies and whole-table consumers protect
  deletion. Dynamic expressions and unresolved metadata remain subject to Review.
- Detail-row expressions that refer to a whole table and partition data-coverage
  expressions are included in conservative cleanup protection.
- Item details use larger text and a responsive content area. Parent-table links
  and back navigation make it easier to inspect the containing table. Global
  warnings collapse on detail pages so the selected object remains prominent.

## Install

- Windows: download `semantic-model-cleaner-windows-x64-0.4.0b3.zip` and its
  `.sha256` sidecar, verify the checksum, and extract the complete ZIP before
  running `Semantic Model Cleaner.exe`. The executable is unsigned.
- Python: install the `.whl` or source `.tar.gz`; Python 3.11 or newer is required.
  Both artifacts include SHA-256 sidecars.

See the [quick start](https://github.com/MrPerfectH/Semantic-Model-Cleaner/blob/v0.4.0b3/docs/quickstart.md)
and [support boundaries](https://github.com/MrPerfectH/Semantic-Model-Cleaner/blob/v0.4.0b3/docs/support.md).

## Validation and boundaries

Publication requires source checks, a fresh wheel installation, and browser-driven
verification of the downloaded Windows ZIP in a separate job. The workflow retains
verification evidence. Synthetic regressions cover working slicers, cleanup-preview
parity, metadata dependencies, calculation groups, and parent-table navigation.

Analysis covers local TMDL/PBIR projects and the selected reports. “No observed
usage” does not prove that external consumers or dynamic expressions are absent.
Review limitations and exact saved-plan differences before applying changes.
BOM-prefixed TMDL scopes remain read-only. This is a prerelease, not a stable release.
