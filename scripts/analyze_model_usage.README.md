# analyze_model_usage.py

Deterministic analyzer for Power BI PBIR + TMDL projects.
The supported workflow is exactly one semantic model and one or more reports.

It cross-references:
- semantic model items from `*.SemanticModel`
- report references from `*.Report`

and classifies each measure/column as used or not used.

## Quick usage

From a standard workspace root:

```bash
python3 scripts/analyze_model_usage.py . --format full
python3 scripts/analyze_model_usage.py . --format unused
python3 scripts/analyze_model_usage.py . --format json
python3 scripts/analyze_model_usage.py . --format xlsx
python3 scripts/analyze_model_usage.py . --format xlsx -o report.xlsx
```

From non-standard folder layout:

```bash
python3 scripts/analyze_model_usage.py \
  --models-path /path/to/models_root_or_model_dirs \
  --reports-path /path/to/reports_root_or_report_dirs \
  --format full
```

Interactive selection (terminal UI):

```bash
python3 scripts/analyze_model_usage.py . --interactive --format full
```

Filter by model and report name (substring, case-insensitive):

```bash
python3 scripts/analyze_model_usage.py . --model Sales Finance --report Executive Regional --format unused
```

- `--model` accepts one or more substrings.
- `--report` accepts one or more substrings.
- Filters are OR-based within each flag.
- The final selection must resolve to exactly one semantic model.
- `--models-path` / `--reports-path` can point to:
  - a directory to search recursively
  - a standard workspace root
  - a direct `.SemanticModel` / `.Report` folder

## What it scans

1. Model items:
- Measures (with `isHidden` detection)
- Columns (with `isHidden`, `isKey`, `isNameInferred`/`isDataTypeInferred`, `sortByColumn` detection)
- Calculated columns
- Relationship columns (`relationships.tmdl`)
- RLS filter references (`model.tmdl` and `roles/*.tmdl`)
- Hierarchies and their backing columns

2. Report references:
- Visual field/query definitions (`visual.json`)
- Visual interactions from pages (`page.json`)
- Page-level filters (`page.json` → `filters`)
- Drillthrough target fields (`page.json` → `drillthrough`/`drillthroughFilters`)
- Hierarchy level references (`HierarchyLevel` in visual JSON)
- Bookmarks (`*.bookmark.json`)
- Additional definition JSON files (fallback scan for refs outside standard files)

Discovery behavior:
- If `Models/` or `Reports/` exists under a search root, those folders are used first.
- Otherwise it falls back to recursive search for `*.SemanticModel` / `*.Report`.

3. DAX dependency analysis:
- Measure → measure dependencies (qualified and unqualified references)
- Measure → column dependencies (for indirect column usage)
- Transitive closure so helper measures used by used measures are marked `INDIRECT`

## Status meanings

- `USED`: directly referenced in report JSON.
- `USED (Relationship)`: only used via model relationship.
- `USED (RLS: ...)`: only used in RLS filters.
- `USED (Key Column)`: marked as `isKey` in the model — required for table integrity.
- `USED (Hierarchy: ...)`: column backs a hierarchy that is referenced in a report.
- `USED (Sort Column for: ...)`: column is the `sortByColumn` target of another used column.
- `INDIRECT (via: ...)`: not directly in report, but needed by other used measures.
- `NOT USED`: no usage found by the analyzer.

## Removal risk

Each `NOT USED` item is classified by removal risk:

- **Safe**: visible, no DAX dependents — developer didn't hide it, likely unneeded.
- **Review**: hidden or key column — developer intentionally kept it, may still be needed.
- **Caution**: other DAX expressions reference this item (even if those are also unused).
- **Do not remove**: inferred column (auto-generated by Power BI, cannot be manually deleted).

## Important notes / limits

- Matching is case-insensitive.
- If DAX uses dynamic metadata tricks (`NAMEOF`, string-built references, calc-group indirection), static analysis can still miss some usage.
- If a model has ambiguous duplicate measure names across tables and DAX uses unqualified `[MeasureName]`, the analyzer may over-approximate dependencies.
- Invalid JSON files are skipped.

## Output formats

- `full`: summary + table-level summary + detailed matrix with hidden indicator, usage context, and removal risk.
- `unused`: compact list of only `NOT USED` items, sorted by removal risk (safe first), with hidden indicator and fully unused tables highlighted.
- `json`: machine-readable result including `isHidden`, `isKey`, `isInferred`, `sortByColumn`, `removalRisk`, and per-table stats.
- `xlsx`: Excel workbook with 3 sheets:
  - **Summary** — metrics, models/reports, table-level stats.
  - **Details** — one row per item (deduplicated), with status, risk, pages used, visual types, contexts. Unused rows are highlighted.
  - **All References** — one row per usage reference (full matrix), with conditional formatting for risk.

Requires `openpyxl` (`pip install openpyxl`). Without `-o`, the file is auto-named from the model name.

## Output file (`-o` / `--output`)

All formats support `-o` to write to a file instead of stdout:

```bash
python3 scripts/analyze_model_usage.py . --format full -o report.md
python3 scripts/analyze_model_usage.py . --format xlsx -o analysis.xlsx
```

For `xlsx`, if `-o` is omitted the file is named `<model>_usage_analysis.xlsx` in the current directory.

## Web App (interactive cleaner)

A local Flask web app for browsing analysis results and performing cleanup actions on TMDL files.

### Start the app

```bash
# From a standard workspace root
python3 scripts/app.py .

# With explicit paths
python3 scripts/app.py \
  --models-path /path/to/Model.SemanticModel \
  --reports-path /path/to/Report.Report

# Custom port
python3 scripts/app.py . --port 8080
```

Then open http://127.0.0.1:5001 in a browser.

Requires `flask` (`pip install flask`).

### Features

- **Discover** — auto-detects one `.SemanticModel` and one or more `.Report` directories
- **Analyze** — runs the full analysis and displays results in a sortable, filterable table
- **Filters** — status, risk, type, table, hidden, display folder, free-text search
- **Bulk select** — "Select all Safe", "Select all visible", checkbox per row
- **Actions** on selected items:
  - **Move to folder** — sets `displayFolder` property (e.g. "Safe to delete")
  - **Hide / Unhide** — adds or removes the `isHidden` flag
  - **Delete** — removes entire measure/column block (requires typing "DELETE" to confirm)
- **Automatic backup** — timestamped copy of `.SemanticModel` created before first action
- **Git awareness** — warns if working directory has uncommitted changes
- **Auto-refresh** — re-analyzes after each action to show updated state

### Files

- `scripts/app.py` — Flask server with REST API
- `scripts/tmdl_writer.py` — TMDL modification engine (set folder, hide, delete)
- `scripts/templates/index.html` — single-page web UI
